# 飞猪酒店参考价接入设计

## 目标

在现有高德可信酒店 POI 链路上补充飞猪酒店参考价。高德继续负责酒店身份、地址和坐标；飞猪只负责按已确认的酒店名称、城市、入住日期、离店日期和成人数查询最低浏览价。任何飞猪故障都不得阻断旅行计划生成。

飞猪报价属于推荐阶段的参考单晚价，不是已锁定的订单总价。界面必须提示房型、税费、早餐、库存和退改规则以飞猪页面为准。

## 架构与数据流

新增独立的 `FliggyHotelPriceSource`，通过服务端 `HotelPriceSource` 接口提供报价，禁止把代理调用、Token 或飞猪响应解析混入 `AmapResearchSources`。

1. 规划器仍从高德取得酒店候选。
2. 分段 Agent 只能返回高德候选的 `poi_id`；服务端用候选表还原酒店对象，忽略 Agent 生成的名称、价格、地址和来源字段。
3. 行程分段完成后，服务端按连续住宿段收集唯一酒店及真实入住区间，并并发查询飞猪；相同查询键只执行一次。
4. 成功报价覆盖到对应住宿日，预算按每间房每晚参考价计算；失败时保留高德酒店并标记价格不可用。

报价查询键由酒店名称、城市、入住日期、离店日期和成人数组成。飞猪代理不支持房间数，因此 `rooms` 不进入上游请求，前端和预算不得把返回价格描述为多房订单总价。

## 接口与配置

`HotelPriceQuote` 至少包含：

- `provider: "fliggy"`
- `hotel_name`
- `nightly_price`
- `currency: "CNY"`
- `source_url`
- `checked_at`
- `method: "lowest_nightly_browse"`

酒店结果写入：`estimated_cost`、`source_url`、`price_checked_at`、`price_method` 和 `price_status: "estimated"`。酒店身份字段继续使用高德的 `source: "amap"` 与 `source_hotel_id`；另设 `price_source: "fliggy"`，避免把实体来源和价格来源混为一谈。

服务端环境变量：

- `FLIGGY_PROXY_TOKEN`：必填；缺失时禁用飞猪报价。
- `FLIGGY_PROXY_URL`：可选，默认使用已验证的腾讯云飞猪代理地址。
- `FLIGGY_PRICE_TIMEOUT_MS`：默认 `3000`，范围 `500..5000`。
- `FLIGGY_PRICE_CACHE_TTL_SECONDS`：默认 `300`，范围 `0..1800`。

Token 不进入运行时设置接口、浏览器响应、日志或前端构建产物。当前社区代理只作为可替换适配器实现；未来接入飞猪官方接口时不改变规划器和前端数据契约。

## 匹配与失败策略

飞猪返回酒店必须通过规范化名称匹配。完全匹配优先；品牌与剩余名称组合相似度低于 `0.75` 时拒绝报价。只接受有限、严格大于零的人民币价格和 HTTPS 跳转链接。

请求超时、非 2xx、非 JSON、结构变化、无匹配酒店、零价或无效链接时返回“无报价”，不重试、不抛出到计划主流程。5 分钟内的相同成功结果和无报价结果均缓存，减少重复请求。日志只记录提供方、耗时和错误类别，不记录 Token 或完整用户请求。

## 用户体验

有报价时显示“飞猪参考价 ¥X/晚”，并提供“去飞猪查看”链接；旁边固定提示“房型、税费、库存及退改规则以飞猪页面为准”。无报价时沿用“暂未取得酒店报价”，不得展示 `0` 元，也不得用预算兜底值伪装成飞猪价格。

预算来源说明区分“酒店信息：高德”和“参考价：飞猪，查询于 YYYY-MM-DD”。中文、英文和法文文案保持等价。

## 测试与验收

- 单元测试先失败后实现：请求参数、名称匹配、价格解析、HTTPS 校验、超时降级、无 Token 禁用、缓存命中和错误不外泄。
- 规划器测试：Agent 虚构酒店被拒绝；可信高德酒店获得飞猪报价；报价失败仍完成计划；连续住宿只查询一次；预算按房间数和住宿晚数计算。
- 前端测试：三种语言显示参考价及免责声明，链接安全打开，无报价不出现零元。
- 真实验收：使用公开日期查询上海外滩华尔道夫，确认飞猪价格、来源链接和时间戳落入生成计划；代理请求不超过 3 秒，失败时计划仍可完成。

## 非目标

本次不实现飞猪登录、房型详情、锁价、下单、价格监控或携程/美团/途牛等多平台比价，也不把社区代理返回值宣传为最终可订价格。
