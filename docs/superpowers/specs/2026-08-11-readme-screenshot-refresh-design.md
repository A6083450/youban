# README 与应用截图更新设计

## 目标

让 README 准确反映当前游伴版本，并用一组精简、连贯的截图展示从开始规划到查看和执行行程的核心体验。

## README 更新范围

- 更新“本次更新”，覆盖新版规划首页、今日行程反馈、行程总览、一键导航和日历导出。
- 重写“应用展示”，不再沿用旧版按功能堆叠的 8 张 PC 图和 5 张移动图。
- 截图标题、说明和替代文本使用当前界面中的普通中文，不写实现细节。
- 其余安装、架构和部署内容仅在发现与当前仓库明确不一致时做必要修正，不做无关改写。

## 截图清单

### PC 端

1. 登录：昵称登录与品牌入口。
2. 规划首页：旅行需求输入和进行中行程入口。
3. 对话确认：AI 理解需求并继续规划。
4. 生成进度：当前品牌化生成状态。
5. 行程总览：旅行蓝图、路线与代表体验。
6. 详细日程：每日安排，并展示导航和加入日历入口。

桌面截图使用 1440 x 900 视口。

### 移动端

1. 规划首页。
2. 规划过程。
3. 今日行程。
4. 行程详情与分享入口。

移动截图使用 390 x 844 视口。

## 数据与拍摄方式

- 启动当前分支的真实前后端，并确认访问的是游伴页面。
- 使用中文界面和同一份代表性行程，保证截图之间形成连续流程。
- 优先复用本地已有的完整行程；若没有可用数据，仅通过现有测试夹具或应用支持的本地流程准备截图数据，不修改产品逻辑。
- 截图前等待页面稳定，避免加载中骨架、通知浮层、调试元素或意外滚动位置进入成片。
- 语义化命名新图片，并删除 README 不再引用的旧应用截图。

## 验收

- 逐张检查桌面和移动截图，确认没有遮挡、截断、空白地图或异常状态。
- 使用文件元数据验证所有图片的像素尺寸。
- 检查 README 中每个本地图片路径都存在，标题与实际画面一致。
- 运行 README 链接检查、`git diff --check` 和前端构建；截图流程涉及的页面再做一次浏览器复核。
- 本次不改业务功能，不提交运行时数据、下载文件或浏览器状态。
