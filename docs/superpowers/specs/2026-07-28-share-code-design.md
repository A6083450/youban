# 游玩计划分享码设计

**日期：** 2026-07-28  
**主题：** 在现有分享链接与二维码之外，增加可复制、可直接输入的 8 位分享码  
**状态：** 已确认，待实施

---

## 1. 背景

现有游玩计划分享功能已经支持公开只读链接和二维码。分享 URL 的路径参数就是计划的 8 位 `planId`，后端公开分享接口也使用该 ID 读取已完成的最终行程。

本次扩展把这个 8 位 ID 正式呈现为“分享码”。发送方可以直接把分享码告诉他人；接收方无需拼接 URL，也无需先寻找隐藏菜单，可以在登录页或已登录侧边栏直接输入并查看公开只读计划。

本设计是 `docs/superpowers/specs/2026-07-26-plan-share-design.md` 的增量扩展。若两份文档在分享码范围或公开接口描述上冲突，以本文和当前实现为准。

## 2. 目标与非目标

### 目标

- 分享弹窗明显展示当前计划的 8 位分享码，并支持单独复制。
- 未登录访客在登录页直接看到分享码输入框。
- 已登录用户在侧边栏“新建计划”下方直接看到同一输入框；移动端抽屉复用该侧边栏内容。
- 正确分享码直接打开现有 `/share/{code}` 公开只读页。
- 格式错误、计划不存在或计划尚未完成时给出明确反馈，并提供就地重试入口。
- 保持现有公开分享的只读权限边界不变。

### 非目标

- 不新增分享码数据表、映射服务或短链服务。
- 不支持自定义分享码、重置、撤销、有效期或访问统计。
- 不改变计划 ID 的生成规则。
- 不允许通过分享码查看用户资料、创建对话、处理中数据或编辑计划。

## 3. 分享码规则

- 分享码就是已完成计划的 `planId`，当前为 8 位小写十六进制字符。
- 输入时移除空白并转换为小写，再按 `^[0-9a-f]{8}$` 校验。
- 页面显示和复制的分享码统一使用小写形式。
- 分享码与分享链接使用同一安全模型：任何拿到分享码的人都可以查看该计划的最终只读结果。
- 后端继续通过专用 `GET /api/trip/share/{task_id}` 返回数据；私有 `/api/trip/status/{task_id}` 不对访客开放。

## 4. 用户流程

### 4.1 发送分享码

1. 计划拥有者在结果页点击“分享”。
2. 分享弹窗按“分享链接、分享码、二维码”的顺序展示三种方式。
3. 用户点击分享码旁的复制按钮。
4. 页面提示“分享码已复制”，用户可以把 8 位码发送给他人。

### 4.2 未登录访客输入

1. 访客打开应用后进入登录页。
2. 登录区域下方直接显示“查看朋友分享的计划”分区和分享码输入框。
3. 访客输入或粘贴 8 位分享码，点击“查看”或按回车。
4. 前端校验通过后跳转到 `/share/{code}`，无需登录即可查看只读计划。

### 4.3 已登录用户输入

1. 用户在桌面侧边栏或移动端抽屉中看到“输入分享码”区域。
2. 输入后点击查看或按回车。
3. 跳转到同一个公开只读计划页，不把分享计划加入当前用户的计划历史。

### 4.4 输入失败

- 空输入：查看按钮禁用。
- 格式错误：输入框下方显示“请输入 8 位分享码”，不发请求、不跳转。
- 分享码不存在或计划尚未完成：公开页显示明确错误和同一个分享码输入组件，用户可直接修改后重试。

## 5. 组件与职责

### 5.1 `ShareCodeEntry.vue`

新增一个可复用的分享码输入组件，负责：

- 输入值、空白移除、小写转换和 8 位格式校验；
- 回车与查看按钮提交；
- 通过 Vue Router 跳转 `/share/{code}`；
- 显示格式错误；
- 支持紧凑侧边栏样式和完整登录页/错误页样式。

组件不读取计划数据，也不持有用户身份。它只负责把合法分享码转换成公开路由。

### 5.2 `SharePlanModal.vue`

在现有链接区与二维码区之间增加分享码区：

- 标签“分享码”；
- 显示 `planId` 的只读文本或输入框；
- 使用复制图标按钮，并提供可访问名称；
- 复用现有剪贴板降级逻辑；
- 链接复制和分享码复制使用各自的成功/失败提示。

### 5.3 `LoginView.vue`

在昵称登录按钮和登录提示下方增加清晰分隔区：

- 分隔标题“查看朋友分享的计划”；
- 完整宽度的 `ShareCodeEntry`；
- 不要求先登录，不把分享码输入藏在链接、弹窗或二级菜单中。

### 5.4 `App.vue`

在侧边栏“新建计划”按钮下方增加紧凑版 `ShareCodeEntry`。侧边栏本身已被桌面与移动端抽屉复用，因此不另建移动端入口。

公开分享页仍使用无侧栏布局，不显示当前用户、历史计划或分享码输入区。

### 5.5 `ShareView.vue` 与 `Result.vue`

- 正确分享码继续渲染现有只读 `Result`。
- 公开请求失败时，`Result` 把加载失败事件交给 `ShareView`。
- `ShareView` 切换为错误状态，显示错误文案和完整 `ShareCodeEntry`，避免访客返回登录页后才能重试。
- 路由参数变化时清除旧错误并重新加载。

### 5.6 国际化

中文、英文、日文新增一致的分享码文案，至少覆盖：

- 分享码标签；
- 复制分享码与复制成功/失败；
- 登录页和侧边栏输入区标题；
- 输入框占位、查看按钮和格式错误；
- 分享码不存在或计划尚未完成；
- 输入其他分享码。

## 6. 数据与权限边界

数据流保持简单：

1. `ShareCodeEntry` 只做本地格式校验并导航。
2. `ShareView` 通过只读 `Result` 请求 `GET /api/trip/share/{code}`。
3. 后端仅在任务存在、状态为 `completed` 且有最终结果时返回 `plan_id`、`status` 和序列化后的 `result`。
4. 其他情况统一返回公开安全的 `404`，不泄露任务是否属于某个用户、是否失败或正在处理。

分享码不会触发以下私有接口：

- 计划创建对话；
- 用户计划历史；
- 预算或 Agent 编辑操作；
- 私有任务状态与失败详情。

## 7. 界面与响应式要求

- 分享弹窗顺序固定为“分享链接 → 分享码 → 二维码”。
- 分享码使用独立边界和等宽字体，按钮使用复制图标并带工具提示或可访问名称。
- 登录页输入区直接可见，不使用折叠、菜单或仅文字链接。
- 侧边栏输入区位于“新建计划”下方，保持紧凑但完整显示输入与提交按钮。
- 375px、768px 和桌面宽度下，输入、按钮和错误文案不得横向溢出或互相遮挡。
- 输入框设置最大长度并支持回车提交；按钮和输入都有明确标签及焦点状态。

## 8. 错误处理

- 格式错误保留原输入，并在组件内部就地提示。
- 公开接口 `404` 使用用户可理解的统一文案，不展示服务器堆栈或内部任务状态。
- 公开请求网络失败显示“暂时无法读取分享计划”，保留重试输入。
- 复制失败时保留可选中的分享码，允许用户手动复制。
- 错误状态不自动跳转登录页，因为查看分享计划本身无需登录。

## 9. 测试与验收

### 自动测试

- 分享码规范化：去空白、转小写。
- 分享码格式：空、少于 8 位、超过 8 位、非十六进制、合法 8 位。
- 后端公开接口继续只返回已完成结果，并拒绝不存在或未完成任务。
- 现有私有状态接口继续对未授权请求返回 `403`。
- 生产构建和现有前端工具测试通过。

### 真实浏览器验收

- 分享弹窗显示正确分享码，复制结果与计划 ID 一致。
- 未登录登录页首屏能明显看到并使用分享码输入框。
- 已登录桌面侧边栏和移动端抽屉能明显看到并使用输入框。
- 合法分享码进入正确的 `/share/{code}` 只读计划。
- 非法格式停留原地并显示输入错误。
- 不存在或未完成的分享码显示错误和重试输入，不跳登录页。
- 公开页继续隐藏侧栏、聊天、分享按钮和预算编辑操作。
- 375px、768px、1280px 下无横向溢出、遮挡或文字截断。

## 10. 验收标准

- [ ] 发送方可以在分享弹窗复制 8 位分享码。
- [ ] 未登录访客无需寻找菜单即可在登录页输入分享码。
- [ ] 已登录用户可以在侧边栏或移动端抽屉输入分享码。
- [ ] 输入合法分享码可以打开对应公开只读计划。
- [ ] 格式错误、无效码和网络错误都有明确、可重试的界面。
- [ ] 分享码不会扩大现有公开只读接口的数据范围。
- [ ] 三种语言、三档视口、自动测试、构建和真实浏览器验收全部通过。
