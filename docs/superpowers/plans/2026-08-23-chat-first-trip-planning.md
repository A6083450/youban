# Chat-First Trip Planning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver fast Pi-powered conversational trip intake, replace the immediate confirmation card with an in-chat draft and visible actions, and preserve explicit confirmation before multi-agent generation.

**Architecture:** Add a tool-free lightweight Pi Agent turn to the LLM client and route trip parse/confirm through it. Keep incomplete drafts as hidden conversation state, render only ready drafts as normal assistant Markdown with inline actions, and retain the existing signed confirmation ledger and `PiTripPlanner` generation path.

**Tech Stack:** Bun 1.4, TypeScript, Elysia 1.4, `@earendil-works/pi-agent-core` 0.84.2, `@earendil-works/pi-ai` 0.84.2, `pi-subagents` 0.53.0, Vue 3, vue-element-plus-x, vue-i18n, bun:test.

**Spec:** `docs/superpowers/specs/2026-08-23-chat-first-trip-planning-design.md`

## Global Constraints

- Chinese and English remain the only product languages.
- Trip intake must remain Pi Agent powered and must not load planning Skills, business tools, or subagents.
- `/api/trip/plan` still requires a one-time signed execution token.
- Incomplete drafts never display confirmation actions.
- Ready drafts render inside a normal assistant bubble, never as a modal, dialog, or standalone card.
- Existing multi-agent planner, migrated data, image serving, task recovery, ownership, and retry contracts remain unchanged.
- Browser testing uses `browser-use` only and reuses the existing local tab.
